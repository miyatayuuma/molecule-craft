# 酸素経路・全部入り構成の比較検証

この文書は改修前の比較記録です。現在の配置とCHO版の結果は [CHO完成ロードマップ](cho-completion-roadmap.md) を参照してください。

2026-09-05。ゲームの性能値・保存形式・搭載制限は変更せず、実ゲームのエンジンと資源精算を使用。

## 判断と次の作業

**構成の選び分けは成立するが、経路・戦法は「支流＋燃焼併用」に偏る。次の作業は、流れ・配置・報酬の改修案作成に絞る。** 分子性能や搭載制限を変える根拠にはしない。

H₂は近道を正面突破でき、燃焼併用で7.90秒帰還。CO₂は正面では全9条件で捕獲されたが、燃焼で横を回れば11.52–11.55秒で帰還できる。支流ではH₂併用が8.37–8.40秒、CO₂併用が10.65–10.68秒。seed 1の正味H/C/Oはそれぞれ **−79/+22/+378** と **+88/−8/+333** で、H₂は速さ・C/O回収、CO₂はH温存と遠征全体の正味に利点がある。どちらかが全元素・時間・帰還の強さで全面的に優位、とはいえない。

成功した基準63走行に対するずれ252走行はすべて正常帰還した。噴射がある走行でも±150msで成功し、今回の成功例は厳密な一瞬の入力だけには依存しない。両構成が噴射剤を使わず同じように攻略できる本道・迂回も存在するが、それだけで全経路の速さと収支が最善になるわけではない。

一方、**酸素採集の効率を優先すると支流の燃焼併用が強い**。H₂近道より帰還が約0.5秒遅いだけで、支流の正味Oはseed 1で+378（近道+118）。CO₂支流は本道より約8.5秒速く、正味Oは+333（本道+127）。両方とも入力ずれに耐えたので、この優位を入力の難しさで相殺できている証拠はない。ただし本道は噴射剤を消費せず、消費原子総数やH消費を抑えられるため、全資源目的での完全支配とは呼ばない。

偏りの候補原因は、支流の4採集レーン・塵価値3に対し、近道は1レーン・価値2、本道は2レーン・価値2という配置と、燃焼時の採集半径加算40の組合せ。支流の短い逆流の間を燃焼で高速採集でき、長い逆流で時間と冷却を使う本道より多く持ち帰る。これはコードと観測が整合する原因仮説であり、個別要因の寄与を切り分けた実験はまだない。

次の改修案では、支流の塵帯を燃焼の広い採集範囲で一度に取り切りにくい位置へ分ける案と、本道の逆流・静かな渦に採集上の利点を付ける案を、同じ比較条件で検討する。H₂の速度とCO₂のH温存の差、および迂回の別解を残すことを評価条件にする。**今回は改修を実施していない。実機での案内・操作感、入力の認識しやすさ、人間の成功率は未確認**で、自動検証の結果とは分けて扱う。

## 成立した攻略例

以下はseed 1。時刻はアンカー出発からの秒数で、操作の説明用であり一瞬の入力を要求する指定ではない。

- H₂の近道：燃焼を保持して近道へ入り、強流の手前で1回噴射。その後燃焼を再開し、合流点で保持を離して帰還ロック。7.90秒、正味H/C/Oは−70/+7/+118。
- H₂の支流：燃焼で進み、逆流手前に2回噴射。各噴射の勢いで薄い逆流2つを越える。8.37秒、正味−79/+22/+378。
- CO₂の支流：燃焼で進み、4つの逆流それぞれで噴射して、その間は燃焼を再開。10.65秒、正味+88/−8/+333。
- CO₂の近道迂回：強流の手前で左外側へ回り、燃焼で周囲の逆流を抜けて元の航路へ戻る。噴射0回、11.52秒、正味−11/+5/+100。H₂でも同じ結果。
- 本道：両構成とも噴射剤を使わず燃焼と静かな渦の休止で帰還できる。全部入り・休止ありは19.20秒、正味−17/+4/+127。水なし休止の既存対照も23.12秒で帰還し、冷却剤必須の鍵にはなっていない。


## 実験条件と読み方

主比較は H₂＋CH₄＋O₂＋水 と CO₂＋CH₄＋O₂＋水。各タンクは独立した現行容量まで満載。`drive` は燃料・酸化剤を搭載する指定で、実際の使用は `policy` に分離した。実際の酸素アンカー `REGIONS.oxygen`（170, −8090）から出発し、敵・採集・消費を有効にした。固定 seed は 1 / 71 / 2026、基準60fps、上限65秒。到達は合流点の半径95への進入、正常帰還はその後0.8秒のロックを捕獲されずに完了すること。

- 噴射中心 (`burst`)：薄い逆流の直前で噴射。長い逆流を持つ本道と迂回路では、圧力がある間だけ燃焼で補助する。
- 燃焼継続 (`continuous`)：移動中は燃焼を保持し、薄い逆流で噴射。エンジンの通常動作どおり、噴射中は燃焼が一時停止し、支払い済みの燃焼時間を保持する。
- 節約 (`economy`)：圧力が正の区間だけ燃焼し、薄い逆流の直前で噴射。噴射中心との操作が一致する区間もある。

全主比較で既存の静かな渦の休止制御を有効化。目標点から30以内かつ熱>20で休止し、熱≤20で再開する（水搭載時にも適用）。航路の次の点まで22以内で目標点を進める。噴射は実際の逆流幅内（中心±115）かつゲート手前 `gate.y < y < gate.y + depth/2 + 30` で要求し、クールダウン等の可否はエンジンが決める。元スクリプトの中心±45制限は物理的な障害幅より狭く、検証用操作の人工的な失敗を生んだため外した。

迂回路は近道の強流より手前から (−300,−9020) → (−470,−9120) → (−470,−9390) → (−300,−9530) と回り込み、元の航路へ復帰する。強流外の圧力370も通常どおり作用する。正面突破と迂回は別の経路として表示する。

収支は **帰還で実際に得た原子 − 一遠征で消費した原子**。未使用タンク分は損失に含めない。回収前の原子数は `collected`、精算後は `returnedAtoms`、H/C/O別消費は `consumedAtoms`、正味は `netByElement`。捕獲では通常の塵損失・端数繰越を適用する。`loss` と `cargoDust` は塵単位、他の収支表は原子単位。時間切れは `returnType=timeout` とし、帰還原子・正味収支は未確定 (`null`)。燃焼パケットは購入時に一度だけ消費計上し、未燃焼時間は `driveBuffer` に別記する。

## 操作のずれへの比較

基準で正常帰還した各構成・経路・方針・seedを対象に4種類を**個別に**試した。噴射時刻は基準走行の成功した噴射要求時刻を記録し、全要求を−150msまたは＋150msして再生する（60fpsで9フレーム）。可否は通常の残量・クールダウン判定に従い、失敗した要求を追加で救済しない。進路ずれは航路の目標点をx方向−30または＋30ずらし、噴射はその走行の位置から判定する。出発地点と最終回収中心は固定。時間ずれと進路ずれは重ねない。

全走行の残量・初回費用・切替数・噴射時刻・塵損失・収支は `--matrix` のJSONに出力される。`--case` に `burstTimes`（秒配列）と `timingOffset`、または `lateralOffset` を指定すればずれ走行を個別再現できる。基準の `actualBurstTimes` をそのまま `burstTimes` に渡す。
